# Sage FP8 blk128 on SM100/SM103

The blk128 entry point matches the existing blk64 FP8 argument order:

```python
bsa_fp8_blk128_fwd(
    q_fp8, k_fp8, v_fp8, q_sfs, k_sfs, v_sfs,
    q2k_block_index, topk_num, softmax_scale=None,
    *, block_sizes=None, q2k_block_nums=None, kv_splits=1,
)
```

It returns one BF16 `[B,H,Sq,128]` tensor. `bsa_fp8_fwd` additionally accepts
`sparse_block_size=64` (default) or `128`; the named blk64 API and its automatic
split policy remain available. SM120 supports blk64 only.

## Input and numerical contract

- Q/K/V: E4M3 BHSD, D=128, MHA, positive B/H/Sq/Sk. Valid noncontiguous views
  are materialized. Q and KV sequence lengths need not be multiples of 128.
- Scales: FP32 Q `[B,H,Sq]`, K `[B,H,ceil(Sk/16)]`, V `[H,128]`. Reshapeable
  scale views are accepted. `quantize_sage_bhsd` produces these six tensors
  from contiguous BF16 BHSD inputs, using centered K and the Sage rounding
  recipe. Its optimized FP32 K reduction can differ at FP8 midpoint ties;
  numerical tests retain explicit scale and attention-error limits.
- Indices: int32 `[B,H,ceil(Sq/128),capacity]`, containing 128-token KV block
  indices. The live prefix is selected by `topk_num`, or by int32
  `q2k_block_nums=[B,H,ceil(Sq/128)]` when supplied. Counts may be odd or zero;
  without per-row counts, scalar top-k is at least one. Metadata values must
  describe valid blocks and fit the index capacity.
- `block_sizes`: optional int32 valid-token counts for each KV block, with
  shape `[N]`, `[B,N]`, or `[B,H,N]`, where `N=ceil(Sk/128)`. The kernel also
  respects the physical tail. Empty optional metadata tensors mean absent.
- Split counts: integers 1 through 256. Split producers use FP32 partials and
  natural-log normalization statistics; the shared native combine handles
  empty splits. The default is one because measured 2/4/8-way splits did not
  improve the covered workloads. There is no public FP8 LSE or backward API.

The implementation uses native E4M3 QK/PV Tensor Cores, FP32 accumulators and
a rounded-probability denominator fused into PV. The base class contains the
shared transfers, scale handling and epilogue; the fused subclass owns the
selected pipeline. BF16/FP16 blk128 and the existing blk64 kernels keep their
separate implementations.

The shared quantizer runs two or three Triton kernels. An optional C++ host
launcher reduces Python dispatch and allocation overhead on warmed calls.
It retains kernel handles and checked launch metadata, never input tensors
or results. Missing build tools, unsupported kernel ABI or active Triton
instrumentation use the regular Triton path. `BSA_FP8_NATIVE_QUANT=0` selects
that path before import. Both paths use the input device's current stream;
native/fallback equivalence and changed inputs are covered by tests.

## Native AOT

```bash
make aot-fp8-blk128 FP8_BLK128_AOT_DIR=/shared/bsa-fp8-blk128-aot

# Or build only the target and variants required by a deployment:
CUTE_DSL_ARCH=sm_100a python -m csrc.fwd.sm100_blk128.aot_build \
  --output-dir /shared/bsa-fp8-blk128-aot --target-arch sm_100a \
  --kv-splits 1,2,4,8 --block-sizes-modes 0,1,2,3 --block-nums both
```

The default matrix exports 32 producers and three combines per architecture.
Artifacts contain `.o`, `.h`, `.so` and a manifest, scoped by host architecture
and `sm_100a`/`sm_103a`. Installed packages can invoke the builder as
`python -m block_sparse_attention.csrc.fwd.sm100_blk128.aot_build`.

Set `BSA_FP8_BLK128_AOT_DIR` to the bundle root or target directory.
`BSA_FP8_BLK128_AOT_ONLY=1` prohibits attention JIT compilation. The existing
global `BSA_SM100_AOT_ONLY=1` also applies; blk64 still uses its own
`BSA_SM100_AOT_DIR`. This does not precompile the separate Triton quantizer.
Missing variants may fall back to JIT outside strict mode; incompatible or
corrupted artifacts raise an error. Source, DSL/CUDA version, target, host
architecture and library checksum are validated.

The public interface is part of both source fingerprints. Rebuild existing
blk64 AOT bundles after this source update as well as building the new blk128
bundle, even though the blk64 kernels themselves are preserved.

After replacing artifacts at the same path in a running process, call
`clear_fp8_blk128_aot_runtime_cache()` from the blk128 `aot_runtime` module.
Strict dispatch checks artifacts before consulting any warmed JIT entry.

## Validation and performance

```bash
python -m pytest tests/test_bsa_fp8_blk128.py \
  tests/test_bsa_fp8_blk128_api.py tests/test_bsa_fp8_blk128_splitkv.py \
  tests/test_bsa_fp8_fwd.py tests/test_bsa_fp8_quant.py \
  tests/test_sm100_aot.py tests/test_sm100_aot_dispatch.py tests/test_packaging.py -q

# Run on the target GPU after building the default blk128 matrix above:
BSA_TEST_FP8_BLK128_AOT_DIR=/shared/bsa-fp8-blk128-aot \
  python -m pytest tests/test_sm100_fp8_blk128_aot.py -q

# Fresh quantization plus attention, including allocations and dispatch:
python tests/bench_fp8_blk128.py --suite all --fp16 --rounds 4
```

The benchmark measures BF16, FP16, FP8 attention, quantization, and actual
fresh quantization-plus-attention separately. End-to-end results are measured
directly, not obtained by adding independent medians. `--mode graph` is a
separate sustained CUDA Graph measurement and must not be compared with
ordinary-call results.

Before integration, the selected kernel and quantizer passed B200/B300
functional, stream, split, packaging and strict native-AOT validation, with
representative racecheck/memcheck runs reporting zero errors. The 2026-10-12
regression used Torch 2.12.0a0+5aff3928d8.nv26.05, CUDA 13.2, CUTLASS DSL 4.5.2
and Triton 3.7.0. It measured four rounds per shape against the faster of BF16
and FP16, retaining all raw samples:

| Scope | Shapes winning all four rounds | Worst individual-round speedup |
|---|---:|---:|
| B200 short | 9/9 | 1.050649x |
| B300 short, independent run | 9/9 | 1.039481x |
| B300 full short/long matrix | 21/21 | 1.048218x |

These are observations of the selected implementation before integration,
not guaranteed speedups. Historical B200 long-sequence losses remain open;
some later runs win with very small margins. Further B200 long-sequence
optimization starts from this integrated baseline.

Provenance: selected fused-kernel SHA256
`255462db77bcd47f2af100c3845dcf77ccd99a1a026116bc4b099d3b7295aded`;
pre-integration regression revision `9bcbcb93a6531a1243e30433acd5f1664ca88a3a`.
The independent experiment checkout and its durable
`checkpoint/parallel-regression-20261012` archive retain raw measurements and
unsuccessful candidates. Those candidates are not part of this implementation.

## Integration verification

The integrated tree preserves the existing `6b4f851` blk64 kernels, AOT
implementation, tail handling and tests. All 58 existing interface functions
are unchanged; blk128 uses the existing native combine ABI. At integration,
the blk128 kernel and quantizer matched the selected implementation above.
The subsequent source cleanup is recorded below.

Actual checks on both GPUs, using the same pinned toolchain:

| Check | B200 | B300 |
|---|---:|---:|
| JIT, API, shared blk64/quantization, dispatch and packaging | 263 passed | 264 passed |
| Rebuilt blk128 native AOT, strict execution and fallback | 46 passed | 46 passed |
| Rebuilt existing blk64 BF16/FP8 native AOT | 5 passed | 6 passed |

The initial suites have 63/62 conditional skips, including AOT cases that are
then rerun with actual artifacts as shown above. Other skips cover SM120,
two-GPU cases, optional `flashinfer_vx`, and opt-in standalone builder tests.
The extra B300 native blk64 case exercises its hardware row-max path. Both
35-library blk128 bundles and the required blk64 libraries were archived;
their library checksums and source fingerprints match the integrated tree.

A two-round ordinary-call smoke measures nine short cases and the long case
`B=1,H=8,Sq=464640,Sk=466560,topk=364`, retaining all 4,000 raw timing samples.
Both GPUs win both rounds on all nine short cases; the worst round speedups
are 1.056680x (B200) and 1.066702x (B300). The long case wins at 1.297327x and
1.311472x on B300. On B200 it measures 1.053955x and **0.982189x**: the second
round is about 1.81% slower than the faster half-precision path. Accuracy,
finite-output and exact-repeat checks pass, but B200 long-sequence performance
stability remains unresolved. This smoke is not a new full 21-shape regression.

The [2026-10-15 blk64/blk128 analysis](blk64-blk128-analysis-20261015.md)
adds a pinned B200 memory/instruction profile, a scheduling control and an
audit of the earlier frequency traces. On the representative long shape,
blk128 halves TMA input traffic and runs faster despite lower SM frequency;
FP8's higher L2 hit rate versus BF16 does not explain the blk128-versus-blk64
gap. The earlier case8 traces show substantial execution-history-dependent
frequency variation. Clock locking remained unavailable, and the original
small-loss call had no simultaneous frequency trace. These findings qualify
the earlier stability concern without claiming a new full-matrix regression
or an exclusive stage-time decomposition.

Integration receipts, source manifests, artifacts and raw logs are preserved
locally under `agent/agent_space/blk128-integration-20261012/`.

## Source cleanup (2026-10-15)

Review of `85c04e4` and `83d1c61` removed the unreferenced FP8 partial-MMA
helper and Q-load wrapper, obsolete scale-vector setup, and unused local
descriptors, phase variables, imports and internal arguments. The remaining
PTX helper namespace names its functions explicitly. AOT utilities retain
the CUDA-version and checksum re-exports used by the builder and loader.
Public interfaces, quantization, synchronization and the blk64 kernels are
unchanged.

Removing unused source still changes the blk128 AOT fingerprint, so existing
blk128 bundles must be rebuilt for this revision. The blk64 AOT fingerprint
is unaffected by this cleanup.

The 27 Python files touched by the two feature commits pass all Pyflakes
checks. On the pinned integration toolchain, the cleaned source passed:

| Check | B200 | B300 |
|---|---:|---:|
| JIT, API, split, shared quantization/blk64, dispatch and packaging | 263 passed, 63 skipped | 264 passed, 62 skipped |
| Rebuilt blk128 native AOT, strict execution and fallback | 46 passed | 46 passed |

The first suite skips 40 native blk128 cases until artifacts exist; the
second row executes them against rebuilt artifacts. Other conditional skips
cover unsupported hardware, optional dependencies and opt-in blk64 AOT runs.
Both targets exported 32 producers and three combines; library checksums and
source fingerprints were verified. Existing blk64 native libraries were not
rebuilt in this cleanup. Logs, source manifests and artifact verification are
under `agent/agent_space/fp8-cleanup-20261015/`.

### Cleanup performance spot check (2026-10-15)

Compared `a45cad2` (before cleanup) with `76e2c05` on B200 and B300, using three
representative shapes from the existing benchmark pattern, B=1, H=4, D=128
and one KV split. On each GPU, both kernel versions were compiled separately
in one process with isolated JIT caches, identical public-wrapper bytecode
and the same input tensors. Each timing mode used three rounds of 40 samples
per version, alternating before/after launch order. Compilation and
sparse-index construction were excluded; the full chain quantized Q/K/V
afresh each call.

All six shape/GPU cases produced exactly equal before/after outputs, including
fresh quantization, repeated calls and CUDA Graph replay. The comparison
against BF16 also passed the existing error thresholds.

| GPU | Q / KV length | Top-k | Before quantization + attention (ms) | After (ms) | Time change |
|---|---|---:|---:|---:|---:|
| B200 | 4,096 / 4,096 | 8 | 0.054960 | 0.054848 | -0.204% |
| B200 | 234,240 / 235,712 | 184 | 7.035440 | 7.033696 | -0.025% |
| B200 | 695,040 / 697,408 | 544 | 59.149038 | 59.106209 | -0.072% |
| B300 | 4,096 / 4,096 | 8 | 0.052448 | 0.052048 | -0.763% |
| B300 | 234,240 / 235,712 | 184 | 5.615632 | 5.617248 | +0.029% |
| B300 | 695,040 / 697,408 | 544 | 46.844048 | 46.830095 | -0.030% |

These are medians over 120 ordinary CUDA-event samples per version. The
attention-only event median changes across both GPUs ranged from -0.546%
to +0.036%; attention-only CUDA Graph median changes ranged from -0.511%
to +0.033%. No material slowdown was observed in these six cases. Clocks
were not locked, and GPU-state snapshots are not per-kernel frequency
measurements. This checks the cleanup, rather than remeasuring
FP8-versus-BF16 speedup.

The first B200 batch-queue attempt did not run. A retry using the permitted
`interactive-isolated-short` QoS acquired B200 in approximately one second
and completed all three cases. B200 used four CPU cores, 16 GiB host memory
and four OpenMP threads; B300 used 16 CPU cores, 64 GiB host memory and eight
OpenMP threads. Each before/after comparison used the same resource allocation.
All task allocations were released.

`agent/agent_benchmark/fp8-cleanup-check-20261015/`. B200 records and the
combined six-case summary are in
`agent/agent_benchmark/fp8-cleanup-check-b200-retry-20261015/`; the copied B300
